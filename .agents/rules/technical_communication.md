# Rule: Professional Technical Communication & UX Writing

This rule enforces professional technical communication standards across all documentation in the CodeNova repository.

## Guiding Principles

1. **Target Audience & Purpose:**
   - Always tailor content for target readers: judges, evaluators, and engineers.
   - Balance executive summaries (for 60-second scanning) with granular technical specifications (schemas, APIs, cryptography).

2. **UX Documentation Design:**
   - Treat documentation as a user interface.
   - Use generous white space, bold lead-ins, structured markdown tables, and clear visual diagrams.
   - Highlight vital constraints with standard alerts (`[!NOTE]`, `[!TIP]`, `[!IMPORTANT]`, `[!WARNING]`).

3. **Writing & Editing Standards:**
   - **Active Voice:** Write in the active voice using present tense.
   - **Simple, Direct English:** Replace dense jargon with clear, unambiguous phrasing.
   - **ABC Structure:** Organize major documents with an **Abstract** (overview), **Body** (technical depth), and **Conclusion / Action** (actionable checklist / takeaways).
   - **Fact-Checked Citations:** Ground problem statements with empirical data, cited sources, and clickable file links.
